1. Engineering Problem

Vehicle integration engineers need to move quickly from raw CAN frames to meaningful signal evidence. A clean viewer helps identify missing heartbeats, out-of-range values, scaling mistakes, and software integration issues.

Portfolio goal: Make the project read like an engineering tool used for integration, validation, debugging, or controls development — not just a classroom exercise.

2. System Architecture

CAN Log (.asc/.blf/.csv) + DBC File ↓ Frame Parser → DBC Decoder → Signal DataFrame ↓ ↓ ↓ Trace Table Signal Browser Plot/Validation Engine ↓ CSV + HTML Report Export

3. Core Features

Tool Features

  • Load sample CAN log and DBC file
  • Decode message IDs into physical signal values
  • Search by signal name, message name, or CAN ID
  • Plot vehicle speed, steering angle, brake pressure, yaw rate, SOC, etc.
  • Run simple validation rules such as min/max, timeout, and stuck-signal checks

Validation Metrics

  • Decode success rate
  • Missing-frame count
  • Signal timeout count
  • Out-of-range samples
  • Exported engineering report
